# 园区网关 UDP / TFTP 本地 NAT 演练

用 **FastAPI + 真实 UDP 套接字** 在本机演练园区网关的公网端口复用问题:
公网 UDP 端口有限, 普通回包与 TFTP 换源端口的首包都要接住。

## 解决的问题

1. **普通会话**: 内网主机经网关公网端口访问上游, 回包只认原上游端点
   (上游 IP + 原端口), 同公网端口上不同上游端口的会话可共用。
2. **TFTP 样例**: 首包发到熟知端口, 上游暂扣后从**另一个源端口(TID)**回包。
   - 首包到达前: 会话接受该上游 IP 的**任意源端口** (范围 1-65535),
     因而独占一个公网端口(与任何范围都重叠);
   - 首包到达后: 立即按**实收源端口**收窄为单端口, 新会话可按收窄范围
     重新参与同端口共用分配。
3. **分配纪律**: 同一公网端口上各会话可收回包的源端口范围不得重叠;
   并发受理时绝不移动旧会话, 无合规端口才拒绝(409), 拒绝时原分配不变。
4. **懒绑定**: 公网端口只在会话首次发包时才 `bind`, 最后一个会话删除/
   迁移后立即解绑; 空闲端口不占套接字。

## 目录结构

```
app/
  engine.py    NAT 引擎: 端口池、会话范围、真实 UDP 收发与三元组分发
  upstream.py  样例上游: 3 个回显端口 + 1 个 TFTP(暂扣首包、换端口回包)
  schemas.py   Pydantic 请求模型
  main.py      FastAPI 路由(交互式文档 /docs)
tests/drill.py 端到端演练脚本(仅用标准库)
Dockerfile / docker-compose.yml / requirements.txt / run_local.sh
```

## 启动

### Docker Compose

```bash
docker compose up --build
# 打开 http://localhost:8000/docs
```

UDP 演练全部发生在容器 loopback 上(网关、上游、内网端点同为 127.0.0.1),
宿主只需映射控制面 8000 端口, 无需映射公网端口池。

### 本地直接运行

```bash
./run_local.sh            # 自动使用 .venv 或 .pylibs
# 或: PYTHONPATH=.pylibs python3 -m uvicorn app.main:app --port 8000
```

## /docs 一轮演练流程

1. `POST /round/setup` — 设公网端口池、每端口会话上限、绑定地址。
2. `POST /upstream/start` — 同一上游 IP 起 3 个回显端口 + 1 个 TFTP 端口,
   可设 `default_detain_ms` 暂扣时长。
3. `POST /endpoints` — 建若干模拟内网端点(真实 UDP 套接字)。
4. `POST /sessions` — 建 `normal` / `tftp` 会话, 返回分配的公网端口与
   当前接受范围; 无合规端口返回 409。
5. `POST /sessions/{id}/transmit` — 正文试传(UTF-8 或十六进制),
   返回**实际发包端口**。
6. 查询:
   - `GET /ports` 各公网端口占用、范围、是否已绑定;
   - `GET /sessions/{id}` 会话事件、锁定端口、实际发包端口历史;
   - `GET /dispatch` 分发结果(来源地址、源端口、本地收包端口、匹配会话、
     是否交付、TFTP 锁定记录);
   - `GET /endpoints/{id}/messages` 内网端点实收正文(hex + text, 原样核对)。
7. `POST /round/reset` 重置本轮(释放全部公网绑定)。

## 分发规则

公网套接字收到 UDP 包后, 按 **(来源地址, 源端口, 本地收包端口)** 匹配:

- 本地收包端口定位公网端口上的会话集合;
- 来源地址必须等于会话登记的上游 IP;
- 源端口必须落在会话当前接受范围内;
- 范围互斥保证至多一个会话命中, 正文**字节原样**转发到对应内网端点;
- 无匹配记一条 `matched_session=null, delivered=false` 的分发记录, 不投递。

TFTP 首包命中未锁定会话时, 在同一把锁内完成: 锁定实收源端口 →
按收窄范围重新分配公网端口(不移动其他会话)→ 必要时懒绑定新端口、
解绑变空闲的旧端口。

## 实测

`python3 -I tests/drill.py` 共 28 项断言, 覆盖:

- A. 普通会话同端口共用、实际发包端口可查、正文(含二进制)原样交付、
  不串会话、删除后解绑、空闲端口不绑定;
- B. 容量/范围打满后 409, 且拒绝前后端口分配逐字节不变(不移动旧会话);
- C. TFTP 首包前范围 1-65535 独占端口 → 暂扣后换源端口回包 →
  锁定实收端口(与上游 TID 一致)→ 范围收窄后同端口可共用 →
  锁定后杂包拒绝分发;
- D. 10 路并发建会话: 3 端口 × 上限 2 = 受理 6、409 拒绝 4,
  无超配, 未试传端口不绑定, 试传后仅该端口懒绑定。

## 缺项 / 边界说明

- 演练拓扑在单台机器 loopback 内完成, 未模拟真实公网 IP 与多宿主路由;
  上游 IP 用字符串相等匹配。
- 未实现 TFTP 协议语义(RRQ/DATA/ACK/超时重传), 只复现其"NAT 首包换端口"
  行为; 上游对后续包做原样回显。
- 无会话空闲老化/超时回收, 会话靠 DELETE 或 round reset 释放。
- 正文以 UTF-8 或十六进制承载, 未做应用层分片/重组。
- 控制面无鉴权, 定位为本地演练工具。
